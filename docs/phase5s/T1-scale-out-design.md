# Phase 5S / T1 — design of the scale-out (design for C5S.1–C5S.6)

distributed-fmm.md §14 plans the scale-out as work packages S1–S7, from counts simulated
in one process and costs measured on one locust rank. Nothing in it ran across nodes. This
task turns §14 into a design that settles the decisions that change code in T2–T9:
- what a rank holds of the top of the tree, and how it learns it without an all-gather
  (S1);
- who owns each `Global` box, how multipoles reach the boxes that need them, bit for bit,
  and what stays replicated (S2);
- how the result is checked where no one-rank run fits (S7);
- how the cut balances work rather than points (S3);
- when the construction and the O(P) collectives need replacing (S4, S5);
- how all of it is tested and measured on Kathleen.

It writes that design as `docs/design/scale-out.md`, for sign-off by hand before T3. It is
the Phase 5S counterpart of Phase 5 T1. It writes no Rust in the workspace, apart from
throwaway measurement programs in the scratch directory (not committed), and job scripts
it may keep under `tools/kathleen/` if they are reusable.
