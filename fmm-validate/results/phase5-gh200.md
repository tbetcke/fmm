# Phase 5 scaling on locust's GH200 (T10, C5.3)

The distributed host FMM of Phase 5 on 1–72 ranks of locust's 72 Grace cores, and at 256
and 512 ranks oversubscribed for correctness and memory: strong and weak scaling stage
by stage, the M2L strategy at p = 8, ranks against threads, overlap, communication,
redistribution and load balance at 8 and 72 ranks, memory per rank, the errors against
the direct sum and the one-rank run, and the device on several ranks as a correctness
table (docs/phase5/T10-scaling.md, design docs/design/distributed-fmm.md §11). Run on
2026-10-10: the sweeps of the brief 11:06–13:18, the strategy runs and the repeats
13:20–13:53, the CUDA gate 13:55–13:59 (after the timing runs).

**Every figure below is one node over shared memory: ranks are processes on locust's
one Grace CPU (72 cores, one NUMA node), exchanging through Open MPI on that machine.**
None is inter-node scaling. Every time is *measured (locust, ranks × threads as given,
release build)*; the memory model of distributed-fmm.md §9.2 is labelled *model*, and
so is anything derived from it.

**Not measured:**
- **Inter-node scaling**: locust is one node (docs/phase5/README.md, decision 2). The
  command that would measure it is in phase5-m3max.md §12 (and the header of
  `tools/scaling/run.sh`); it builds on Linux (here), and no result is claimed from it.
- **The device on several ranks as a timing** (decision 3): §12 is a correctness table.
- **Times above 72 ranks**: the 256- and 512-rank runs share 72 cores and are never
  timed (§10).
